# 默认独立自动验收，而不是默认人工签收

状态：已实现（完成策略、自动终态、平台观测、DSH 迭代入口与受保护验收 case 均已落地；真实平台闭环证据见实施记录）。

本次用户明确纠偏：用户在 DeepSeek Harness 表达需求，Agent 自动完成需求整理、规划、实现、独立校验、修复/必要时重规划、验收交付及后续迭代。普通交付默认采用 independent_auto；human_review 仅由用户主动选择。依据为本次原始请求、v0.5 需求确认文档与 v0.3 的 DSH 底座补充。这是需求变更，不是伪造原流程的 owner PASS。

## 被替代的旧规则

v0.5 的三处固定人工触点、最终 owner Journey Review 硬门禁，以及仓库仅交付只读状态 CLI 的范围，不再是新流程的默认契约。新需求及已授权范围中的 HOW 自行决定；只有实质产品取舍、新权限、费用或破坏性操作需要集中询问。已有明确需求授权不再要求重复 GitHub 评论或手填回执。

## 保留的不变量

Contract / Coverage / Evidence / Baseline、Required 和 Spine 的全量实际执行、精确版本/环境绑定、独立验证来源、远端保护、CI 晋升与累积历史均保留。自动验收不是开发 Agent 自称完成；不能执行的验证明确标为缺失或限制，不能生成 PASS。旧 Evidence、owner 记录、4 次 Candidate attempt 与 1 次 Replan（远端当前值仍需核验）不得改写或清零。不得通过换根因名称、降标或改 Slice 名规避失败。

## 执行与验证的 seam

按用户 A–F 已指定的产品接口验证：真实 DSH 的自然语言需求/恢复/修改入口；实际交付程序的公共行为；独立验证/晋升入口；公开预算与恢复查询。单元测试仅作回归，不代替 DSH 端到端证据。使用独立测试配置，不修改正在使用的 profile。

## 预算原则

成功执行仍保留在 attempt 历史，但不能计为同根因失败或无进展。失败/Replan 的累计预算跨会话和重规划保留；新迭代必须有新的用户需求及可信的已交付起点，不得仅改名重置一个未完成的迭代。
